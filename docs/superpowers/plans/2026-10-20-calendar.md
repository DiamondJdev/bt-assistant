# Calendar Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Calendar tool in the BT macOS app on top of EventKit: permission flow, day/week/month views with "next up", quick create and full edit sheets, recurring edits with `.thisEvent`/`.futureEvents`, live refresh, read-only handling for subscribed calendars, and `calendar_*` tool declarations.

**Architecture:** Date math, event formatting and recurrence mapping are pure functions over a small `CalendarEventItem` value type so they test under `swift test` without calendar access. `CalendarStore` is the only type that touches `EKEventStore`; it is the shared read API other modules (Pomodoro in phase 8) will use. Everything lives in BTKit; BTMac only adds the entitlement, usage string and module entry.

**Tech Stack:** Swift 6, SwiftUI, Observation, EventKit, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-20-pomodoro-and-calendar-design.md`

## Global Constraints

- Swift 6 language mode, macOS 14 minimum. No new package dependencies.
- Do not change `apple/BTKit/Sources/BTKit/ToolModule.swift`. If a task seems to need it, stop and report.
- Modules are `@MainActor @Observable final class`es conforming to `ToolModule`; `snapshot` and `content` are computed.
- EventKit stays the source of truth. No copy of events is persisted.
- Tool names match `^[a-zA-Z0-9_-]+$`.
- Week start follows `Calendar.current.firstWeekday`. Pass a `Calendar` into pure functions so tests can pin it.
- Quick create default: 30-minute event in `eventStore.defaultCalendarForNewEvents`.
- Events on calendars with `allowsContentModifications == false` (school and Google subscriptions) display normally, cannot be edited or deleted, and the UI says "Read-only (subscribed calendar)".
- Never edit or delete events on the owner's real calendars from tests or verification. Manual checks use a duplicate event the agent creates and deletes afterward.
- Tests: `swift test --package-path apple/BTKit` from the repo root. App build: `xcodebuild -project apple/BT.xcodeproj -scheme BTMac -configuration Debug -destination 'platform=macOS' -derivedDataPath /tmp/bt-calendar-build build`.
- Commit messages: `<type>: <description>` ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Editing one occurrence of a weekly class must not move the others; "this and future" must not change past occurrences. (Task 3 manual early check; Task 2 test `spanMapping`.)
2. Daylight saving change weeks: a day still has 24 hour rows and events land at the right local time. (Task 1 test `dayRangeAcrossDSTIsOneCalendarDay`.)
3. All-day and multi-day events: shown in the all-day strip on every day they cover, not as a 24-hour timeline block, and excluded from "next up". (Task 2 tests `nextEventSkipsAllDay`, `multiDayEventAppearsOnEachDay`.)
4. Access denied or restricted: the pane shows the explanation and an "Open System Settings" button, and the snapshot is `nil` instead of crashing or showing an empty calendar. (Task 4 test `snapshotNilWithoutAccess`.)
5. Custom recurrence rules from other apps survive a save that didn't touch recurrence. (Task 2 test `customRuleIsPreservedWhenUnchanged`.)

### Task 2: Event value type, next-up, snapshot and recurrence mapping

**Files:**
- Create: `apple/BTKit/Sources/BTKit/Calendar/CalendarEventItem.swift`
- Create: `apple/BTKit/Sources/BTKit/Calendar/Recurrence.swift`
- Test: `apple/BTKit/Tests/BTKitTests/CalendarEventItemTests.swift`

**Interfaces:**
- Produces:
  - `public struct CalendarEventItem: Identifiable, Equatable, Sendable { public let id: String /* calendarItemIdentifier + occurrence start */; public let eventIdentifier: String /* EKEvent.calendarItemIdentifier */; public let occurrenceStart: Date; public let title: String; public let start: Date; public let end: Date; public let isAllDay: Bool; public let calendarTitle: String; public let colorHex: String?; public let location: String?; public let isRecurring: Bool; public let isEditable: Bool }`
  - `func nextEvent(in items: [CalendarEventItem], after date: Date) -> CalendarEventItem?` (earliest non-all-day event with `start >= date`; if one is in progress, it is not "next")
  - `func items(_ items: [CalendarEventItem], on day: Date, calendar: Calendar) -> (allDay: [CalendarEventItem], timed: [CalendarEventItem])` (an event belongs to every day its interval overlaps)
  - `func calendarSnapshot(items: [CalendarEventItem], now: Date, calendar: Calendar) -> String`. Exact copy: `"Calendar: next is CS 3013 at 2:00 PM (in 40m), id <eventIdentifier>; 3 more events today."`. With nothing next today: `"Calendar: nothing else today."`. "more events today" counts timed events today starting after the next one; omit `; N more events today` when 0; use `1 more event today` for 1. Time formatted with `Date.FormatStyle(date: .omitted, time: .shortened)` in `calendar.timeZone`; "in" uses `Xh Ym` / `Ym`.
  - `enum EditSpan: String, Sendable { case thisEvent = "this_event", futureEvents = "future_events" }` with `var ekSpan: EKSpan`
  - `enum RecurrenceOption: Equatable, Sendable { case none, daily, weekly, biweekly, monthly, yearly, custom(String) }`, `func recurrenceOption(from rules: [EKRecurrenceRule]?) -> RecurrenceOption`, `func recurrenceRules(for option: RecurrenceOption, end: Date?) -> [EKRecurrenceRule]?` (returns `nil` for `.custom` meaning "leave the event's rules unchanged")

- [ ] **Step 1: Write failing tests:**
  - `nextEventSkipsAllDay`, `nextEventSkipsInProgress`, `nextEventIsEarliestUpcoming`.
  - `multiDayEventAppearsOnEachDay`: all-day event Mon–Wed shows in `allDay` for Mon, Tue and Wed only.
  - `snapshotNextAndCount`: now 13:20, events 14:00 "CS 3013", 16:00, 18:00 → `"Calendar: next is CS 3013 at 2:00 PM (in 40m), id cs; 2 more events today."` (exact string; use the fixed calendar from Task 1 and `en_US` locale).
  - `snapshotNothingLeft` → `"Calendar: nothing else today."`.
  - `spanMapping`: `.thisEvent.ekSpan == .thisEvent`, `.futureEvents.ekSpan == .futureEvents`, raw values `"this_event"` / `"future_events"`.
  - `recurrenceRoundTrip`: each of daily/weekly/biweekly/monthly/yearly → rules → option returns the same case; biweekly is weekly interval 2.
  - `customRuleIsPreservedWhenUnchanged`: weekly on Mon+Wed rule → `.custom(_)`, and `recurrenceRules(for: .custom(...), end: nil) == nil`.
- [ ] **Step 2: Run** `swift test --package-path apple/BTKit --filter CalendarEventItemTests`. Expected: compile failure.
- [ ] **Step 3: Implement.** `EKRecurrenceRule` can be built without store access.
- [ ] **Step 4: Run** same command. Expected: pass.

# Pomodoro Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Pomodoro tool in the BT macOS app: work/break timer stored as `phase` + `endsAt`, menu bar countdown, phase-end notifications, SwiftData `FocusSession` log with today's totals, a now-playing card that controls the Music app, and `focus_*` tool declarations.

**Architecture:** Timer logic, persistence, notifications and UI live in `apple/BTKit` behind small injected seams (clock, notifier, now-playing source) so they test under `swift test`. `apple/BTMac` supplies the Mac-only parts: the `MenuBarExtra`, the Music Apple Events controller and the shared SwiftData `ModelContainer`.

**Tech Stack:** Swift 6, SwiftUI, Observation, SwiftData, UserNotifications, ScriptingBridge/NSAppleScript (BTMac only), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-20-pomodoro-and-calendar-design.md`

## Global Constraints

- Swift 6 language mode, macOS 14 minimum (`platforms: [.macOS(.v14), .iOS(.v17)]` stays as is). No new package dependencies.
- Do not change `apple/BTKit/Sources/BTKit/ToolModule.swift`. If a task seems to need it, stop and report.
- Modules are `@MainActor @Observable final class`es conforming to `ToolModule`; `snapshot` and `content` are computed.
- Code that could run on iOS goes in BTKit. Mac-only code (menu bar, Apple Events) goes in BTMac. BTKit must still compile for iOS: guard AppKit usage with `#if os(macOS)` or keep it out.
- SwiftData models: every attribute optional or defaulted, no `@Attribute(.unique)`.
- Tool names match `^[a-zA-Z0-9_-]+$`.
- Defaults: work 25 min, short break 5 min, long break 15 min, long break after every 4 work phases.
- Phases do not auto-advance. Stop logs a partial work phase only if it ran at least 60 seconds.
- `.pbxproj` edits stay minimal: new BTMac files and `INFOPLIST_KEY_*` build settings only.
- Tests: `swift test --package-path apple/BTKit` from the repo root. App build: `xcodebuild -project apple/BT.xcodeproj -scheme BTMac -configuration Debug -destination 'platform=macOS' -derivedDataPath /tmp/bt-pomodoro-build build`.
- Commit messages: `<type>: <description>` ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Mac sleeps or the app quits mid-phase: on relaunch the finished phase is logged once with its scheduled end, not twice and not at launch time. (Task 3 test `recoversPhaseThatEndedWhileClosed`.)
2. Pause then resume: the remaining time is preserved exactly and the pending notification is rescheduled for the new end. (Task 3 test `pauseRemovesNotificationAndResumeReschedules`.)
3. Today's total across midnight: a session that ends after midnight counts toward the day it ended in only. (Task 2 test `totalTodayUsesEndDate`.)
4. Music not running or permission denied: the card shows a message and never launches Music by itself. (Task 5 manual check.)
5. Durations edited mid-phase do not change the running phase's `endsAt`. (Task 1 test `changingDurationsDoesNotMoveRunningPhase`.)

### Task 1: Timer state machine

**Files:**
- Create: `apple/BTKit/Sources/BTKit/Pomodoro/PomodoroTimer.swift`
- Test: `apple/BTKit/Tests/BTKitTests/PomodoroTimerTests.swift`

**Interfaces:**
- Produces:
  - `enum PomodoroPhase: String, Codable, Sendable { case work, shortBreak, longBreak }`
  - `struct PomodoroDurations: Codable, Equatable, Sendable { var work: TimeInterval = 1500; var shortBreak: TimeInterval = 300; var longBreak: TimeInterval = 900; var longBreakEvery: Int = 4; func duration(of: PomodoroPhase) -> TimeInterval }`
  - `struct PomodoroState: Codable, Equatable, Sendable { var phase: PomodoroPhase; var startedAt: Date?; var endsAt: Date?; var pausedRemaining: TimeInterval?; var completedWorkPhases: Int }` with `static let idle`, `var isRunning: Bool`, `var isPaused: Bool`, `func remaining(at: Date) -> TimeInterval?`
  - Pure transitions returning a new state plus an optional finished work interval:
    - `func started(at: Date, durations: PomodoroDurations) -> PomodoroState`
    - `func paused(at: Date) -> PomodoroState`
    - `func resumed(at: Date) -> PomodoroState`
    - `func completed(durations: PomodoroDurations) -> (PomodoroState, FocusInterval?)` (phase reached `endsAt`; advances to the next phase, idle, not started)
    - `func skipped(at: Date, durations: PomodoroDurations) -> (PomodoroState, FocusInterval?)`
    - `func stopped(at: Date) -> (PomodoroState, FocusInterval?)`
  - `struct FocusInterval: Equatable, Sendable { let start: Date; let end: Date }`

- [ ] **Step 1: Write failing tests** in `PomodoroTimerTests.swift`:
  - `startSetsEndsAtFromWorkDuration`: idle started at `t0` → `phase == .work`, `endsAt == t0 + 1500`.
  - `completingWorkGoesToShortBreakAndReportsInterval`: completed → phase `.shortBreak`, `endsAt == nil`, interval `t0...t0+1500`, `completedWorkPhases == 1`.
  - `fourthWorkPhaseLeadsToLongBreak`: after 4 completed work phases next phase is `.longBreak`; after the long break completes the next is `.work`.
  - `pauseKeepsRemainingAndResumeRestoresIt`: start at `t0`, pause at `t0+100` → `pausedRemaining == 1400`, `endsAt == nil`; resume at `t0+500` → `endsAt == t0+1900`.
  - `stopUnderSixtySecondsLogsNothing`: stop at `t0+59` → interval `nil`, state idle `.work`.
  - `stopAfterSixtySecondsLogsPartialWork`: stop at `t0+600` → interval `t0...t0+600`.
  - `stoppingABreakLogsNothing`.
  - `skippingWorkLogsElapsedLikeStop`: same 60-second rule, then advances phase.
  - `changingDurationsDoesNotMoveRunningPhase`: running state's `endsAt` unchanged after new durations; next `started` uses the new ones.
  - Partial work while paused: stopping a paused work phase logs `startedAt` to `startedAt + (duration - pausedRemaining)`.
